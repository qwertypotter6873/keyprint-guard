## 1. 사전 오프라인 정량 검증 결과 (`KeyRecs` · `CMU` · 고정 인코더)

두 인코더(`keyprint_net.pt` 17채널, `keyprint_net_9ch.pt` 9채널)의 가중치는 **재학습 없이 고정(Frozen)** 했으며, 모든 보정 통계와 하이퍼파라미터는 `Train(68명) → Validation(10명) → Test(18명)` 및 **분할 간 완전 분리(Disjoint)된 실험 문자열**에서만 학습·선택·평가했습니다.

### 1.1 [모델 차원 ⑤·⑥] 사용자 지정 암호 문자열별 경량 코호트 보정

`Train` 68명의 자유 타건에서 관측 빈도 5회 이상인 388개 키쌍 요약표(`[관측수, 인원수, 상대 DD 중앙값, 개인 간 표준편차]`)를 구축하고, 문자열 길이와 직교하는 7개 전이 구조 특징(`repeat_frac`, `same_finger_frac`, `alt_hand_frac`, `mean_dist`, `dup_pair_frac`, `mean_log_count`, `mean_between_std`)으로 타인 점수 분포 잔차 $(\Delta\mu_9, \Delta\ln\sigma_9, \Delta\mu_{17}, \Delta\ln\sigma_{17})$ 를 추정하는 가중 Ridge 모델을 적합했습니다. 드문 전이가 포함된 문자열은 관측 지지율 $s \in [0, 1]$ 에 비례해 기존 길이별 보정(`dualParamsForLength`)으로 자동 수축($w = \text{clip}(\gamma \cdot s, 0, 1)$)합니다.

| 조건 (`Test` 미관측 18명 × 미관측 문자열) | 보정 방식 | `ROC-AUC` | `EER` | `FRR @ FAR=5%` | `FRR @ FAR=10%` | 문자열 간 `FAR` 표준편차 | 최악 문자열 `FAR` |
| :--- | :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **스마트폰 터치 (`L ≥ 12`, 64종, 29,922회)** | 기존 길이별 보정 | `0.8559` | `22.74%` | `60.21%` | `43.64%` | `12.65%p` | `82.08%` |
| **스마트폰 터치 (`L ≥ 12`, 채택 `ON`, $\gamma=0.7$)** | **문자열별 코호트 보정** | **`0.8609`** | **`22.33%`** | **`58.05%` (`-2.16%p`)** | **`42.12%` (`-1.52%p`)** | **`10.70%p` (`-15.4%`)** | **`74.79%` (`-7.29%p`)** |
| **스마트폰 터치 (`12자` 단독, 16종, 7,432회)** | 기존 길이별 보정 | `0.8213` | `25.53%` | `66.89%` | `52.14%` | `11.11%p` | `82.08%` |
| **스마트폰 터치 (`12자` 단독, 채택 `ON`)** | **문자열별 코호트 보정** | **`0.8266`** | **`25.21%`** | **`65.71%` (`-1.18%p`)** | **`49.78%` (`-2.36%p`)** | **`9.73%p` (`-12.4%`)** | **`74.79%` (`-7.29%p`)** |
| **물리 키보드 (`L ≥ 12`, 64종, 29,922회)** | 길이별 유지 ($\gamma=0.0$ 자동 수축) | `0.9357` | `13.66%` | `34.20%` | `19.60%` | `7.10%p` | `43.75%` |

- **통계적 유의성**: 스마트폰 터치 `L ≥ 12`에서 참가자 단위 1,000회 군집 부트스트랩 95% 신뢰구간이 `FAR=5%` 기준 `[-3.27%p, -1.00%p]`, `FAR=10%` 기준 `[-2.39%p, -0.55%p]`로 0을 포함하지 않고 유의하게 본인 거부율(`FRR`)을 낮추었습니다.
- **물리적 해석**: 터치 입력에서는 홀드·비행시간이 결측되어 연속 반복 문자(`Bookkeeper`, `CoffeeTree` 등)의 타인 기저 유사도($\mu_{17}$)가 평균보다 높고 분산($\sigma_{17}$)이 좁아지는데, 문자열별 보정이 이를 정밀하게 상쇄합니다. 반면 물리 키보드는 `H_curr, H_next, UD, Rollover`가 관측되어 이미 높은 분별력(`AUC 0.9357`)을 가지므로 `Validation`에서 $\gamma=0.0$으로 자동 수축되어 회귀(성능 저하)를 원천 차단했습니다. 브라우저 평가 기록기는 두 점수(`lengthBaseline`, `stringCalibrated`)를 매 판별마다 `0.05 ms` 미만 지연으로 동시 기록합니다.

### 1.2 [데이터 차원 ③] 물리 스위치 변경 시 물리 일관성(`UD = DD - H_curr`) 홀드 보정

기계식(예: 리니어 적축)과 팬터그래프(외장·노트북 내장) 간 작동점·바닥거리 차이로 발생하는 홀드 시간 이동($\Delta h \in \{-25, -15, +15, +25, +35\}\text{ ms}$)에 대해 단순 `H` 채널 이동과 물리 일관성(`UD = DD - H_curr` 및 `Rollover` 동시 재계산) 보정을 비교했습니다(`Test` 18명 문장 과제, 5문장 등록·2문장 질의).

| 교차 스위치 홀드 편차 $\Delta h$ | 무보정 (18자 1위 / 5인 수락률) | 단순 `H`만 보정 (`UD` 불일치) | 스위치 사전치 물리 일관 보정 (`H+UD`) | 무지도 평균 정렬 물리 일관 보정 |
| :---: | :---: | :---: | :---: | :---: |
| `0 ms` (동일 스위치 기준) | `88.37%` / `35.68%` (FAR `0.10%`) | `88.37%` / `35.68%` | `88.37%` / `35.68%` | `89.06%` / `38.75%` (FAR `0.19%`) |
| `-25 ms` | `75.00%` / `19.94%` | `87.50%` / `33.73%` | **`88.37%` / `35.68%`** | **`89.06%` / `38.75%`** |
| `+15 ms` | `77.08%` / `23.55%` | `88.02%` / `35.00%` | **`88.37%` / `35.68%`** | **`89.06%` / `38.75%`** |
| `+25 ms` | `64.58%` / `20.14%` | `87.50%` / `33.64%` | **`88.37%` / `35.68%`** | **`89.06%` / `38.75%`** |
| `+35 ms` | `55.56%` / `19.29%` | `87.15%` / `31.46%` | **`88.37%` / `35.68%`** | **`89.06%` / `38.75%`** |

- 단순 `H` 보정은 `DD - H_curr ≠ UD` 모순을 만들어 롤오버·듀티비 채널에서 잔여 성능 손실(`+35 ms` 수락률 `31.46%`)이 남는 반면, `UD`를 함께 복원한 물리 일관 보정은 전 구간에서 원래 성능(`88.37% / 35.68%` 이상)을 회복합니다.

### 1.3 [데이터 차원 ④] 스마트폰 터치 행동 가중치 $\beta$ 검증 (`KeyRecs` 터치 문장 과제)

| 행동 가중치 $\beta$ 설정 | `Val` 1위 정답률 | `Val` 본인 수락률 | `Val` 외부인 오수락률 | `Test` 1위 정답률 | `Test` 본인 수락률 | `Test` 외부인 오수락률 |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| $\beta = 0.00$ (타건 리듬만 사용) | `77.36%` | `0.00%` | `0.00%` | `71.18%` | `5.62%` | `0.00%` |
| **$\beta = 0.20$ (현재 배포값 = `Val` 최적 $\beta^*$)** | **`82.08%`** | **`22.71%`** | **`1.33%`** | **`71.70%`** | **`16.92%` (`3.0×`)** | **`0.47%`** |
| $\beta = 0.30$ (공격적 가중) | `82.39%` | `42.19%` | `5.21%` | `70.66%` | `28.89%` | `1.97%` |

- 외부인 오수락률 `Val FAR ≤ 2%` 안전 제약 아래 `Validation` 최적값은 현재 배포값과 정확히 일치하는 **$\beta^* = 0.20$** 으로 확인되었으며, `Test`에서 오수락률을 `0.47%`로 억제하면서 본인 수락률을 `5.62% → 16.92%`로 **3배** 높였습니다.

## 2. 4기기 직접 타이핑 실측 프로토콜 매뉴얼 (기계식 · 외장 팬터그래프 · 노트북 내장 · 스마트폰)

### 2.1 실행 및 스마트폰 동시 접속 (로컬 Wi-Fi 다기기 허브 권장)

기본 `localhost` 개발 서버는 노트북 내부 루프백(`127.0.0.1`)에만 열려 스마트폰에서 접속할 수 없고, 모바일 `DeviceMotion` 센서는 보안 컨텍스트(`HTTPS`)를 요구합니다. 아래 **로컬 다기기 실측 허브** 명령 한 줄을 실행하면 동일 Wi-Fi 공유기에 연결된 노트북과 스마트폰을 외부 서버 없이 즉시 연동할 수 있습니다.

```bash
npm --prefix web run field-study
```

1. **자동 구성 항목**:
   - **노트북 접속**: `http://localhost:8780/?eval=1`
   - **스마트폰 권장 (`HTTPS` · 터치 + 모션센서 지원)**: 터미널 또는 노트북 화면에 표시되는 **QR 코드(`https://<노트북_Wi-Fi_IP>:8443/?eval=1`)** 를 스마트폰 카메라로 스캔합니다. 최초 1회 브라우저 안내에서 **`고급 → 안전하지 않음으로 이동(웹사이트 방문)`** 을 누르면 터치 입력과 가속도·자이로 센서(`DeviceMotionEvent`)가 모두 활성화됩니다.
   - **스마트폰 즉시 (`HTTP` · 인증서 확인 없는 터치 전용)**: `http://<노트북_Wi-Fi_IP>:8780/?eval=1` 로 접속하면 경고 화면 없이 곧바로 열리며, 터치 타건·프로필 공유·자동 로그 저장이 동일하게 작동합니다(`DeviceMotion` 센서만 비활성화).
   - **외부 전송 없는 실시간 프로필 공유 & 로그 자동 취합**: 노트북과 스마트폰이 노트북 내부 WebSocket 브로커(`/mqtt`, 방 `#LOCALSTUDY`)로 자동 연결되어 노트북에서 등록한 프로필을 스마트폰에서 즉시 검증할 수 있으며, 어느 기기에서 타이핑하든 모든 평가 레코드가 노트북의 `logs/field_study/field_study_merged.jsonl`에 실시간으로 중복 없이 자동 저장됩니다.
2. **정적 호스팅(GitHub Pages) 단독 사용 시**: 배포 주소 뒤에 **`?eval=1`** 을 붙여 접속하거나 우측 상단 **`[실측·평가]`** 버튼을 누른 뒤 기기별로 `[JSONL 내보내기]` 파일을 받아 합칠 수도 있습니다.
3. 상단 평가 패널에서 **`[✓] 실측 기록 활성화`** 와 **`[✓] 평가 중 템플릿 자동 적응(adapt) 잠금`**(기본 켜짐)을 확인하고, 스위치 간 홀드 재채점·행동 통계·모션 센서 분석을 위해 **`[✓] 원시 타이밍·결측·수정/멈춤 통계 수집 동의`** 에 체크합니다.
4. **비공개 암호 보호**: 허용 목록(24개 공개 실험 문자열)에 없는 개인 지정 문자열을 입력할 때는 원시 수집에 동의하더라도 **원문과 키 정체성(`pairKeys`, 대문자 입력 수단)이 브라우저 내부에서 자동 비식별화(`null`)** 되어 저장됩니다.

### 2.2 참가자별 4기기 역균형(Williams Latin Square) 측정 순서

연습 효과와 피로가 특정 키보드에 쏠리지 않도록 `연구용 참가자 ID`(`P01`\~`P04`)를 입력하면 상단 배너가 아래 순서표를 자동 안내합니다. 외장 기계식과 외장 팬터그래프는 **동일 PC·동일 브라우저·동일 배열**에 번갈아 연결하여 순수 스위치 차이를 비교하는 것을 권장합니다.

| 참가자 ID 그룹 | 1번째 기기 (`day1_slot1`) | 2번째 기기 (`day1_slot2`) | 3번째 기기 (`day1_slot3`) | 4번째 기기 (`day1_slot4`) |
| :---: | :--- | :--- | :--- | :--- |
| `P01`, `P05`, … | 기계식(외장) | 외장 팬터그래프 | 스마트폰 터치 | 노트북 내장(팬터그래프) |
| `P02`, `P06`, … | 외장 팬터그래프 | 노트북 내장(팬터그래프) | 기계식(외장) | 스마트폰 터치 |
| `P03`, `P07`, … | 노트북 내장(팬터그래프) | 스마트폰 터치 | 외장 팬터그래프 | 기계식(외장) |
| `P04`, `P08`, … | 스마트폰 터치 | 기계식(외장) | 노트북 내장(팬터그래프) | 외장 팬터그래프 |

### 2.3 기기별 타이핑 절차 (약 8\~10분 / 기기)

1. **환경 메타데이터 선택**:
   - 현재 연결한 **키보드 종류**(`기계식 · 리니어/넌클릭/클릭`, `외장 팬터그래프`, `노트북 내장 팬터그래프`, `스마트폰 화면 터치`), **한글·영문 입력 방식**(`PC 표준 두벌식`, `모바일 쿼티 두벌식`, `천지인`, `나랏글`, `단모음`), **파지·거치 자세**, **세션 순서**를 선택합니다.
   - 스마트폰 측정 시 **`[모션 센서 권한·측정 시작]`** 버튼을 한 번 눌러(iOS 13+ Safari 권한 팝업 승인) 상태 배지에 실제 수신 주파수(예: `60.0 Hz · 16.7 ms`)가 표시되는지 확인합니다. 손에 들고 엄지로 칠 때(`hand_two_thumbs`)와 책상 위에 평평하게 두고 칠 때(`desk_phone_flat`)를 구분해 측정할 수 있습니다.
2. **동일 프로필 교차 기기 비교 팁**:
   - PC와 스마트폰에서 우측 상단 `[이 브라우저만]` 버튼을 눌러 **같은 비공개 실험용 방 코드**로 입장하면, 기기 A에서 등록한 프로필 템플릿을 기기 B·스마트폰에서 즉시 불러와 실시간 교차 기기 판별을 수행할 수 있습니다. (방 동기화를 쓰지 않고 각 기기 로컬에서만 측정한 뒤 나중에 `.jsonl` 파일들을 하나로 합쳐도 `src/analyze_field_study.py`가 `profileId` 기준으로 자동 연결합니다.)
